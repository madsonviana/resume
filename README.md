### 📜 **GitHub Actions Workflow**  

This repository includes a **GitHub Actions workflow** that automatically converts `RESUME.md` and `COVER_LETTER.md` into **PDFs** whenever changes are pushed to either file.  

The workflow:  
✅ Uses **md-to-pdf** with **Puppeteer** for **accurate PDF rendering**.  
✅ Generates the files as `pdf/RESUME-YYYYMMDD.pdf` and `pdf/COVER_LETTER-YYYYMMDD.pdf`, based on the current date.  
✅ Automatically **commits the generated PDFs** to the repository.  
✅ (Optional) **Sends an email with the latest resume and cover letter PDFs** if the mail secrets (`MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SMTP_SERVER`) are configured.  

👀 **Ensure Workflow Permissions**: Verify that your repository's settings allow workflows to have write permissions:

   - Navigate to your repository on GitHub.
   - Click on the "Settings" tab.
   - In the left sidebar, select "Actions" and then "General".
   - Under "Workflow permissions", ensure "Read and write permissions" is selected.
   - Click "Save" to apply the changes.

   This setting ensures that workflows have the necessary permissions to make changes to the repository.

You can find the workflow configuration in `.github/workflows/convert-md-to-pdf.yml`.  

### **📬 Email Notifications with Gmail or Apple Mail**
Your **GitHub Actions workflow** includes an **optional feature** that automatically sends an email with your **latest resume and cover letter PDFs** whenever `RESUME.md` or `COVER_LETTER.md` is updated. 📄📩  

#### **🔹 How It Works**
- The workflow **checks for the mail secrets** (`MAIL_USERNAME`, `MAIL_PASSWORD`, and `MAIL_SMTP_SERVER`) before attempting to send an email.  
- If they exist, it will:
  ✅ Convert `RESUME.md` and `COVER_LETTER.md` into PDFs in `pdf/`  
  ✅ Attach the **latest resume and cover letter PDFs** to an email  
  ✅ Send the email using the **SMTP server configured in `MAIL_SMTP_SERVER`**  
- If the secrets are **not configured**, the email step is **skipped** to prevent errors.

Both providers send through **SMTP on port 587 (STARTTLS)** using an **app-specific password** — a dedicated password generated by the provider, never your normal login password. Since the SMTP server now comes from the `MAIL_SMTP_SERVER` secret (used by the workflow as `-smtp "$MAIL_SMTP_SERVER"`), **no workflow editing is required** — just set the correct server for your provider:

| Provider   | `MAIL_SMTP_SERVER`              | Port | `MAIL_USERNAME`                   |
|------------|----------------------------------|------|------------------------------------|
| Gmail      | `smtp.gmail.com`                 | 587  | Full Gmail address (e.g., `you@gmail.com`) |
| Apple Mail | `smtp.mail.me.com`               | 587  | Full iCloud address (e.g., `you@icloud.com`) |

#### **🔹 How to Enable Email Sending**

1. **Generate an App-Specific Password from your provider**  
   - **Gmail**: go to [Google App Passwords](https://myaccount.google.com/apppasswords), select **"Mail"**, generate and copy the **16-character password**  
   - **Apple Mail**: make sure **Two-Factor Authentication** is enabled, then go to [Apple Account → Sign-In & Security → App-Specific Passwords](https://account.apple.com/sign-in), click **"Generate..."**, name it (e.g., `GitHub Actions Resume`) and copy the **app-specific password**  

2. **Set Up GitHub Secrets**  
   - Go to your **GitHub Repository → Settings → Secrets and Variables → Actions**  
   - Click **"New Repository Secret"** for each variable:
     - **`MAIL_USERNAME`** → Your email address (e.g., `your-email@gmail.com` or `you@icloud.com`)  
     - **`MAIL_PASSWORD`** → The app-specific password  
     - **`MAIL_SMTP_SERVER`** → Your provider's SMTP server (see table above, e.g., `smtp.gmail.com` or `smtp.mail.me.com`)  

3. **Push an Update to `RESUME.md` or `COVER_LETTER.md`**  
   - GitHub Actions will generate the PDFs and send them via email! 🚀  

#### **🔹 Disabling Email Notifications**
- If you **do not set** `MAIL_USERNAME`, `MAIL_PASSWORD`, and `MAIL_SMTP_SERVER`, the email step will be **skipped** automatically.

📌 This ensures **error-free execution**, whether or not you choose to enable email notifications.
